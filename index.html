How I work

I don't stop at the Figma file.

I work closely with development to make sure the experience survives the transition from design to production.

01 / 06

Stage 01 of 06

  1. 01 Research

    Understand the problem first

    Stakeholder conversations, user needs and business goals, turned into a clear problem to solve.

    Output
    Problem statement · Requirements
    • Interviews
    • Competitor review

  2. 02 UX

    Shape how it should work

    User flows, information architecture and wireframes that settle the journey before any pixels.

    Output
    User flows · Wireframes
    • Figma
    • FigJam

  3. 03 UI

    Design how it looks and feels

    High-fidelity screens, reusable components and clickable prototypes that developers can trust.

    Output
    Figma prototypes · Components
    • Figma
    • Design systems

  4. 04 Frontend

    Build it myself

    Responsive, accessible interfaces written in HTML, CSS and JavaScript, so the design survives handoff.

    Output
    Production-ready UI
    • HTML / CSS
    • JavaScript
    • Accessibility

  5. 05 QA

    Check it before users do

    Cross-device testing, bug fixes and code review across the release cycle.

    Output
    Release-ready build
    • Code review
    • Cross-browser

  6. 06 Ship

    Release and keep improving

    Launch, watch how people use it, and iterate. Features I shipped this way lifted engagement by 20%.

    Output
    Live product · Iterations
    • Release
    • Iteration
